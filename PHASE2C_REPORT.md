# PHASE 2C REPORT

## 1. Architecture Changes

Phase 2C keeps the existing Local Mode and adds a separate static Online Demo
mode:

```text
Local Mode:
  live SNBT -> FTBQ Core -> /api/load -> Viewer UI

Online Demo Mode:
  live SNBT -> FTBQ Core (build time)
    -> normalized JSON + hashed assets in public/demo
    -> static HTTP host
    -> Viewer UI
```

Both modes use the same parser, QuestBook model, TranslationResolver,
DependencyGraph, validator, view model, Minecraft text renderer, and layout
code. Online mode does not call `/api/load`, does not access the local
filesystem from the browser, and does not need Node.js at runtime.

## 2. Online Demo Data Format

`tools/build-online-demo.mjs` writes:

```text
public/demo/manifest.json
public/demo/view-model.json
public/demo/asset-map.json
public/demo/assets/<sha256-prefix>.png
```

`view-model.json` is the serialized viewer adapter model. Offline-only raw
SNBT fields are removed before writing, but normalized text, translations,
unknown task and reward data, Item Components, links, images, reward tables,
dependencies, diagnostics, and chapter/quest metadata remain available to the
Viewer.

`asset-map.json` maps logical item/image references to hashed static asset
paths and contains a `missing` fallback asset.

## 6. Dist Size Analysis

The largest component is `view-model.json`, at approximately 19 MB before
compression. It contains the normalized data for all chapters, quests, tasks,
rewards, translations, links, dependencies, and diagnostics. This is below
the GitHub file-size limit, so aggressive compression was not introduced
without profiling.

Static assets are content-addressed and deduplicated by SHA-256 prefix. The
2027 logical asset references resolve to 1816 unique files.

## 9. GitHub Pages Deployment

The workflow is:

```text
.github/workflows/deploy-pages.yml
```

It runs on pushes to `main`:

```text
install
-> npm run build:demo-data:ci
-> npm run build:static
-> upload dist
-> deploy GitHub Pages
```

GitHub Actions cannot see the local Minecraft instance. Therefore
`build:demo-data:ci` reuses the committed `public/demo/` snapshot when
`FTBQ_QUEST_ROOT` is unavailable. To publish updated quest data:

1. Run `npm run build:demo-data` locally against the desired instance.
2. Commit the changed `public/demo/` files.
3. Push to `main`.

Do not commit the Minecraft instance, `mods/`, `saves/`, `logs/`,
`screenshots/`, `cache/`, or `node_modules/`.

No public URL was published from this machine because the project has no
configured Git remote or hosting credentials. The generated `dist/` directory
and the Pages workflow are ready for that deployment.

## 10. Known Limitations

- The live instance has no chapter image entries, so real-data chapter image
  count is zero. The synthetic fixture still verifies Chapter Image loading
  and rendering.
- The full normalized model is fetched as one initial JSON resource. Code
  splitting or per-chapter lazy loading can be added later if the hosted
  deployment shows a loading-time issue.
- Some model-based mod item textures do not have a simple `item/` or `block/`
  texture path and use the viewer fallback icon.
- The Online Demo is a generated snapshot. It does not automatically update
  when the Minecraft instance changes; regenerate and redeploy after quest
  data changes.
- Online Demo remains read-only. No Edit, Delete, Add, Save, Tauri, installer,
  or Minecraft write path is included.
